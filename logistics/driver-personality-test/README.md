物流現場におけるリアルな状況判断をもとに、ドライバーの安全運転気質を5つのタイプに分類・可視化するWebアプリケーションです。

[🚛DPT 運転性格診断テスト](https://tosane932.github.io/tosane-works/logistics/driver-personality-test/)

現在は[Tosane Works](https://github.com/tosane932/tosane-works)の `logistics/driver-personality-test/` に配置しています。ソースコードと設問データは[このディレクトリ](https://github.com/tosane932/tosane-works/tree/main/logistics/driver-personality-test)で確認できます。

## 🌐 デプロイおよびキャッシュ制御（Cache Busting）

本システムはサーバーレス（純粋なフロントエンドのみ）のSPA構成であるため、既存ユーザーのブラウザ側に古いアセット（`app.js`）が居座り、更新が反映されないリスク（キャッシュの同期ズレ）がありました。
更新時に古いアセットが使われるリスクを減らすため、HTML側で制御する **Cache Busting（キャッシュバスター）** を導入しています。現在は `app.js` と `style.css` にバージョンのクエリパラメータを付けています。

### キャッシュ制御の挙動（Before / After）

`app.js`（診断結果ロジックやUIテキスト）をアップデートした際は、`index.html` 内のスクリプト読み込みタグのクエリパラメータ（バージョン情報）を以下のように更新して出荷（デプロイ）します。

```html
<!-- Before: パラメータなし（古いキャッシュが居座り、手動削除が必要だった状態） -->
<script src="app.js"></script>

<!-- After: 現在のバージョン指定（更新時に値を変更する） -->
<script src="app.js?v=20260710"></script>
```

## 📌 概要
本プロジェクト（通称：DPT）は、運送・物流の現場（トラックドライバー・自販機ルートマン）で長年ハンドルを握ってきた経験（ドメイン知識）と、Webフロントエンドの基礎技術を掛け合わせて開発した **「運転性格診断クイズ（全50問）」** です。

一般的なクイズアプリにある「正解か不正解か」という単純な2値化ロジックではなく、現場のリアルな心理や他者依存のリスクに応じた **「安全性のグラデーション（5段階の傾斜配点アルゴリズム）」** をJavaScriptで実装しています。法律上の正論だけでは割り切れない現場の葛藤やリスク許容度を、自分自身の運転感覚と照らし合わせて客観的に振り返ることができるツールです。

## 🌟 主な機能と特徴
1. **5段階の傾斜配点データ構造**
   - 全50問すべての選択肢に `2.0点` / `1.5点` / `1.0点` / `0.5点` / `0.0点` の5段階評価を定義。データ構造（`testData.js`）の対称性を意識し、最終的に0点〜100点満点で算出される加算式ロジックを構築しています。
2. **5大運転性格ジャンルによるプロファイリング**
   - 算出された合計得点に基づき、現場のドライバー特性を捉えた5つのタイプに判定し、詳細な解説文を出力します。
     - 🟢 **【防衛運転のスペシャリスト】** リスク予知型（85点以上）
     - 🔵 **【物流の円滑剤】** 協調・マナー重視型（65点以上85点未満）
     - ⚪ **【冷静なルーティン】** 鉄のメンタル型（45点以上65点未満）
     - 🟡 **【効率重視の戦略家】** タイムマネジメント型（25点以上45点未満）
     - 🔴 **【改善の余地あり】** 感情先行・直感運転型（25点未満）
3. **過去の受診履歴管理（データの永続化）**
   - `sql.js` のDBをBase64形式でLocalStorageへ保存し、ページをリロードした後も診断スコアと受診日時を復元します。ブラウザのデータ削除・容量制限・保存失敗などによって履歴が失われる場合はあります。
4. **軽量・クリーンな構成 & 拡張性**
   - UIと診断ロジックはバニラJavaScript（Vanilla JS）で実装し、履歴管理に `sql.js` を利用しています。設問をオブジェクト配列として管理し、将来的なJSON外部化やバックエンドAPIからの取得を検討しやすい構成です。これらの拡張は現在未実装です。

## 📊 診断カテゴリ（全50問）

運転性格を「外面的なリスクへの対応」と「内面的なリソースの制御」の両面から捉えられるよう、主要なリスク場面を5カテゴリに分類。
- **公道での他車・歩行者との遭遇** (10問)：狭路での対向車待避、バスの発進予測、割り込み対応など
- **運行管理とスケジュール圧迫** (10問)：出発遅れのリカバリー判断、430規制と渋滞の板挟み、荷主からの時間短縮要求への対応など
- **現場・荷役・バース着け** (10問)：死角の多いバック進入、手積み・手降ろしの安全確保、輪止め設置の徹底など
- **異常気象と物理的限界** (10問)：ゲリラ豪雨、ブラックアイスバーン、強風下の高架橋、アンダーパス冠水時の判断など
- **プロとしての精神力と他車への配慮** (10問)：煽り運転への感情処理、緊急車両への進路の譲り方、割り込みへの反応、疲労時の確認動作の質、単調な長時間走行での集中力維持など

## 🔍 技術的アプローチと最適化（こだわったポイント）

### 1. ブラウザ完結型SQLiteの採用とリソース管理
本アプリはサーバーレス（GitHub Pages等による静的ホスティング）での軽量な実行を前提としつつ、本格的なリレーショナルデータベース（RDB）による履歴管理を疑似体験するため、WebAssemblyで動作する `sql.js` を採用しました。

### 2. データの永続化と技術的トレードオフの割り切り
初期実装では `sql.js` を純粋なインメモリ（RAM上）で起動していたため、ページのリロードや離脱によってデータが消失する課題がありました。これを解決するため、**「SQLの実行状態（バイナリ）をLocalStorageへ退避・復元する」**アーキテクチャを構築しました。

- **課題とトレードオフの考察**:
  データを `INSERT` するたびに、データベース全体のバイナリ（Uint8Array）をBase64文字列へ変換して `LocalStorage` へ同期（書き込み）します。履歴が増えると、全体の変換・書き込みに伴う処理負荷が増える可能性があります。
- **現フェーズでの設計判断（事実ベース）**:
  現在保存するのはID・スコア・受診日時で、1問ごとの回答は履歴DBへ保存していません。保存対象を絞ったシンプルな設計を採用していますが、DB全体のサイズやブラウザの容量制限・処理性能によって負荷は変わります。保存失敗時は例外を捕捉し、診断結果の表示を継続します。保存済みDBの復元に失敗した場合は履歴を初期化します。
- **次フェーズへのロードマップ**:
  今後、1問ごとの詳細ログなど大容量データを扱う場合は、個別保存や非同期I/Oが可能な `IndexedDB` への移行を検討します。

### 3. Fisher-Yatesアルゴリズムによる出題・選択肢のランダム化
- **アルゴリズムの選定と最適化**:
  回答位置の慣れによる偏りを減らすため、配列をランダムに並び替える「Fisher-Yatesアルゴリズム」を採用し、`app.js` 内にシャッフル関数を組み込みました。出題順と各問の選択肢を並び替え、配列の要素数に比例する回数の処理で実行します。
- **非破壊処理による安全運転設計**:
  JavaScriptのスプレッド演算子（`...`）を活用し、元のマスターデータ（`testData.js`）の配列をコピーしてからシャッフルを行っています。各質問オブジェクトもコピーし、元データを書き換えずに並び替えた選択肢を持たせています。

### 4. グローバルスコープの適正配置による堅牢なエラーハンドリング
- **変数スコープの荷詰まり解消**:
  開発プロセスにおいて、最終問題を回答した直後に画面遷移がストップ（クラッシュ）するバグに直面した際、ブラウザのデベロッパーツール（コンソールログ）を用いた検証を実施。原因が `initDb()` 関数内でローカル変数として閉じ込められていた `STORAGE_KEY` にあると特定しました。
- **配線の復旧と他アプリとの衝突回避**:
  キーの配置を関数内から `db.js` のファイル直下（グローバルスコープ）へ移し、`saveScore()` から参照できるようにしました。同時に、キー名へアプリ固有の名称（`truck_driver_test_db_v1`）を使用することで、同じオリジンの他アプリケーションとキーが衝突するリスクを減らしています。
